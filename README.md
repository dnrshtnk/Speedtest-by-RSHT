# Speedtest by RSHT

Лёгкий `sh`-скрипт для проверки сети VPS, сервера или ноды. Есть два режима: проверка соединения до Cloudflare и проверка скорости между двумя своими серверами. Ничего устанавливать через `pip` или `npm` не нужно.

## Требования

- POSIX-совместимая оболочка (`sh`)
- `curl` и `awk` для режима Cloudflare
- `mktemp` для проверки загрузки в режиме Cloudflare
- `iperf3` на обоих серверах только для режима проверки между серверами

## Запуск

Склонируйте репозиторий и запустите скрипт:

```sh
git clone https://github.com/dnrshtnk/Speedtest-by-RSHT.git
cd Speedtest-by-RSHT
sh speedtest.sh
```

Без клонирования репозитория — скачать скрипт через `curl` и сразу запустить:

```sh
curl -fsSLo speedtest.sh https://raw.githubusercontent.com/dnrshtnk/Speedtest-by-RSHT/main/speedtest.sh && sh speedtest.sh
```

Для этого способа нужен доступ к GitHub. Скрипт не требует прав root.

При запуске без параметров появится меню:

```text
1) Cloudflare (current test)
2) Another server (iperf3)
```

### 1. Проверка через Cloudflare

Это прежний режим. Выполняются три небольших запроса для задержки и по два переноса файла размером 5 MiB в каждом направлении. Общий тестовый трафик — около **20 MiB**.

```sh
sh speedtest.sh --cloudflare          # запуск без меню
sh speedtest.sh --size 10 --runs 3   # около 60 MiB трафика, тоже без меню
sh speedtest.sh --download-only      # только скачивание
sh speedtest.sh --upload-only        # только загрузка
sh speedtest.sh -4                   # принудительно IPv4
sh speedtest.sh -6                   # принудительно IPv6
sh speedtest.sh --help
```

`--size` принимает от 1 до 100 MiB на перенос, `--runs` — от 1 до 5 прогонов на направление.

Пример вывода:

```text
Target: Cloudflare (https://speed.cloudflare.com)
Payload: 5 MiB x 2 run(s) per direction
HTTP latency: 18.4 ms (3-request average)
Download: 94.21 Mbps (2-run average)
Upload: 47.63 Mbps (2-run average)
```

### 2. Проверка между серверами

Для настоящего теста скорости между двумя серверами на обоих нужен [`iperf3`](https://software.es.net/iperf/invoking.html). На **другом** сервере запустите серверную часть и оставьте её работающей:

```sh
iperf3 -s
```

Откройте входящий TCP-порт **5201** на другом сервере. На текущем сервере запустите `sh speedtest.sh`, выберите пункт `2` и введите IP-адрес или домен другого сервера. Скрипт проверит скорость в обе стороны: **Upload** — от текущего сервера к другому, **Download** — обратно. Каждый тест длится 5 секунд.

Можно запустить этот режим без меню:

```sh
sh speedtest.sh --peer SERVER_IP_OR_DOMAIN
sh speedtest.sh --peer SERVER_IP_OR_DOMAIN --port 5202 --seconds 10
sh speedtest.sh --peer SERVER_IP_OR_DOMAIN --upload-only
```

Если порт отличается от 5201, запустите другой сервер с тем же портом, например `iperf3 -s -p 5202`. `--seconds` принимает от 1 до 30 секунд. В этом режиме трафик зависит от скорости канала: `iperf3` старается заполнить его в течение заданного времени.

## Что означают результаты

Скорость указана в **Mbps** (мегабитах в секунду). В режиме Cloudflare это среднее по прогонам в каждом направлении. Задержка там же — время до первого байта HTTP-ответа: она включает DNS, установку соединения, TLS и обработку запроса. Это **не ICMP ping**. В режиме `iperf3` выводятся итоговые результаты отдельного прогона для каждого направления.

В режиме Cloudflare скрипт проверяет маршрут от машины, на которой он запущен, до Cloudflare. В режиме `iperf3` — соединение между двумя указанными серверами. Результаты не отражают скорость диска или производительность сайта. На них влияют маршрут, загруженность сети, ограничения провайдера и длительность теста.

Для теста используются [публичные эндпоинты Cloudflare Speedtest](https://github.com/cloudflare/speedtest). При их недоступности или блокировке скрипт завершится с ошибкой. Cloudflare сообщает, что собирает результаты тестов для агрегированной аналитики.
